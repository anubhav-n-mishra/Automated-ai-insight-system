## Responsibilities

Maintainers are expected to:

- Respond to new issues within about a week, even if only to say "not yet".
- Review pull requests, or say clearly that they cannot get to one.
- Acknowledge security reports within 3 working days, per [SECURITY.md](SECURITY.md).
- Keep the correctness guarantees in [SECURITY.md](SECURITY.md) true.
- Cut releases following [CONTRIBUTING.md](CONTRIBUTING.md#releasing).
- Say when they are stepping back, rather than going quiet.

## Response expectations

| | Target |
| --- | --- |
| New issue triaged | 7 days |
| Pull request first review | 7 days |
| Security report acknowledged | 3 working days |
| Security fix released, or a public plan | 90 days |

If one of these slips, saying so on the thread is welcome and will not be taken
badly. A lost notification is far more likely than deliberate silence.

## We are looking for maintainers

This project currently has one maintainer, which is a real risk to anyone
depending on it. If you have been contributing and would like a larger role,
say so — the path is in [GOVERNANCE.md](GOVERNANCE.md), and the bar is judgement
about correctness, not volume of code.

Areas where a second pair of hands would help most:

- **Connectors** — warehouse sources (BigQuery, Snowflake, Redshift, ClickHouse)
- **Rendering** — output formats beyond PowerPoint, and accessibility of the deck
- **Statistics** — significance testing on segment movements, and seasonality
- **Operations** — Helm chart, Kubernetes manifests, horizontal scale-out
